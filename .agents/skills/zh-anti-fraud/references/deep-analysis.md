# 按做局点深拆一件事

用户给出多阶段故事，或追问“属于什么局、哪一步套路我、他图什么”时，用这份指引。先一句话说最显眼的机制和用户眼下能守住什么。随后把故事拆到能回答“为什么那时候我会答应，在哪一步可以抽身”的程度。

## 一、说清属于哪种套路

先用已有的通俗说法，再补结构。例如“熟人说能托关系办事，你在项目落地前不断付钱，后段又出现借权威施压”。写清哪几项怎么叠在一起。涉及法律定性时，以有权机构查明的证据为准。

| 常见机制 | 什么时候才这么叫 | 可比照的材料 |
|---|---|---|
| **借人情索回报** | 前一件事的帮助确实发生，后来又用交情、面子或恩情推动旁的要求 | [人情场与可核事实](social-dynamics.md) |
| **借关系作背书、吹大办事权限** | 从“认识、能问”跳到“保证拿到项目、能办手续”，真正有权决定的一方没作同样承诺 | [有熟人引荐的假贴息贷款案](authority-cases.md) |
| **先交钱再兑现** | 所谓垫款、介绍费或费用的收款人、用途、条件或可核交付对不上。先收费这件事需结合合同与授权判断 | [诈骗类型索引](patterns.md) |
| **拿下一单补上一次投入** | 前一件事没成，改拿新机会、下一笔利润或未到账的钱，让用户继续付出 | 查不计过往损失时，新项目值不值得做。每次新增付款单独核 |
| **借官方名义施压** | 执法、投诉、调查或系统查询的说法，与付款、交资料、入股或到场被绑定 | [冒充机构和独立验证](impersonation.md) |
| **把别人议定的成本转给用户** | 起初只答应咨询、介绍或协助，后来变成替别人买单、交出实物、签个人担保或为结果担责 | 逐项查用户起初同意的范围，以及改变条件的人和受益方 |

## 二、编号还原时间线和关键做局点

先找**每次改变决定的动作**。可从先前帮助、引荐背书、承诺升级、第一次实际付出、落空后换理由、升级施压、事后复核等节点取材。按用户给出的时间排，日期不确定就用“首次见面后”“第一个项目落空后”“另一次联系”。两条支线先分别排，确定先后再合并。

用表或编号。每个关键点都把“做局手段”和“当时怎么破”写在一起：

1. **话和动作。** 谁说了原话、用户从哪里知道、对方当时要什么。把直接行动与别人传的话各写一遍。
2. **当时为什么会接住。** 对照用户讲的需要和感受，例如项目卡住、感谢先前帮助、怕伤关系、想有机会补回已经花的钱、担心消息出错会有后果。自己讲过的感受和根据行为推测的压力分别表述。若当事人当时已经质疑或退出，也写出哪一点让他警觉。
3. **究竟改变了什么。** 例如从“帮问”变成“包办”，从项目费用变个人消费，从一次性变长期，从不成功就停变成再付才能补回。写出这一变化怎样把用户的下一步改为到场、等候、付款、签字、挂名或配合。
4. **实际代价和当时能发现的警讯。** 区分已经发生、对方尝试索取、对方口头许诺。差旅或机会成本与对方收到的钱分开算。用用户在那个时点已能看到的变化指出警讯。后来才查到的事实注明什么时候获得。
5. **那个时点怎么破。** 写一个当时能执行的动作，以及最迟何时、向谁、核到什么才继续。例如“出发前让项目方直接书面确认三件事，没确认就改线上谈”。动作随状态变化，尚未支出就挡在承诺前，已支出就停新增投入并保留对账，已退出就把旧账和新项目拆开。需要谈判时给一句可直接用的话。

典故要贴到节点上。复杂故事优先选两三则各有用处的典故。先说原作的具体动作，再说眼前可能相似的一步、现实中要核哪件事。例如真实给过好处时可用“先寄银而后拐逃”说明过去如何形成信任，另核最初动机。熟人在场或替人传话可用“假马脱缎”。借真实细节冒用机构权威可用“贾廉访赝行府牒”。多人转发同一句时可用“众端参观”。[典故原文与用法](allusions.md)

## 三、解释为什么起作用、对方可能图什么

- **为什么这个故事会往下走。** 从用户当时的话指出一两个最明显的触点，与具体做局点连起来。例如“你直接问做不了怎么办，对方用保证打消顾虑，于是你去了”。复盘这一步的信任和选择，避免用故事给用户定性。
- **目的用行为反推。** 写谁已经得到什么、谁还想得到什么、哪个目的目前只是假设。可观察的利益包括收到款项、获得实物、让别人垫成本、拿到署名或担保、占住独家联系渠道。对方先提“以后会给”，按尚未兑现处理。有人得利仍需另核是否共同安排。
- **把竞争解释讲到能检验。** 比较事前安排、原事真实而中途利用、权限或能力有限又夸口、正常业务加流程差错。指出各能解释哪一段、解释不到哪一段。找一条能区分的记录，例如付款前明确用途，真正负责人在当时的答复，或事前就存在的分工记录。明确指出还不能确认的动机、身份和共同指令。

## 四、办不成后改口，怎么拆

排出**原先怎么承诺、用户按什么承诺付出了什么、失败后怎么改口**。有人事前说能促成，后来改称只负责介绍，明确这两种服务范围和风险承担有何差别。也可能原话只在谈项目能不能做，未承诺由用户成交。用当时原话、收费约定和用户决定出行或付款之前的记录区分。职位、亲属和认识谁要另核，最终签约仍有决定方。

听到“我把钱还给你”，记下它承接的上一句话，核对指哪笔、金额、方式和时间。若从未约定时间，书面请对方给出明确答复日期，用户可以决定自己何时转入下一步处理。把实际到账、部分到账、仍待偿还各自写清。车、设备、原件等财物的返还另排。若后来要求先见人、先做新项目或再付费用，核对这是否是原来退款约定的一部分，让退款和新合作各自谈。遇到“退一部分就签全部结清”，先核协议写的范围与实际到账，再决定是否签。

## 五、如果没有停下来

按已出现过的动作给两三条分支，每条写**下一步可能出现什么、当时看见哪句或哪件事可以确认方向、应怎样应对**。例如“如果承诺还款后又改成下一单结算再返，那么退款期限正在被移到一项不确定的交易上。按原记录核该笔款，先不产生第二笔投入”。若独立核验取得真实书面条件，说明哪些事可以继续。后面如何发展取决于新证据。

复盘结尾突出**最早能发现的一步**、**证据最清楚的一步**和**现在能做的一步**。已确认且有期限的正规事项仍可从原渠道继续。出现付款威胁或逼迫赴约时，先保护人身与财物，留存直接提出要求的人、原话与时间。[先守住自己的利益](own-interests.md)

用户追问怎么判断时，把每个争议写成一项可核验的问题，说明由谁确认、依据是什么、得到什么答复才继续。给一句对应当下决定的警示。[核验清单与警示](verification-and-warning.md)

**虚构示范。** 熟人说能谈成试供，收了服务预付款。随后只发一张名片，改口说他只做介绍，并答应退钱。付款前可先让他写明交付是正式试供协议还是只介绍，及未完成如何退款。改口当天可回“先按原话确认，你说要退的是这笔服务预付款吗？请写明金额和时间”。若他随后改要求先见供应商，见不见由用户按真实采购机会决定，前一笔退款按原约定核对。到账按对应款项记，逾期或追加条件就停止为了等退款而增加的支出。

若用户是在测试或改进技能，只将抽象方法和独立虚构的例子写入可分享的技能。真实故事中的人员、日期、金额和业务细节只在当前分析中使用，除非用户明确要求保存。
